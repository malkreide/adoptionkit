# Umsetzungsplan Stufe 0 – adoptionkit

Spec: `docs/BAUPLAN.md` (Abschnitte 3–12), Entscheide: `docs/DECISIONS.md`.
Paketname ist **adoptionkit** (E1). Wo der Bauplan `deploykit` schreibt, gilt `adoptionkit`.

## Global Constraints

- Python ≥ 3.11, `src`-Layout, Paket `src/adoptionkit/`. Abhängigkeiten: `pydantic>=2.6`, `typer>=0.12`, `pyyaml>=6`, `jsonschema>=4.18`. Dev: `pytest>=8`, `ruff==0.17.3` (Pin, identisch mit `requirements-lint.txt`), `pyright>=1.1.380`.
- Lokale Umgebung: `.venv` im Repo-Root, erstellt mit `uv venv .venv` und `uv pip install --python .venv -e ".[dev]"`. Befehle (nie globales ruff, nie `pip install` ins System-Python): `.venv/Scripts/python.exe scripts/check_ruff_pin.py`, `.venv/Scripts/python.exe -m ruff check .`, `.venv/Scripts/python.exe -m pyright`, `.venv/Scripts/python.exe -m pytest`, `.venv/Scripts/adoptionkit.exe`. Eine vorhandene `.venv` nicht ersetzen, nur mit `uv pip install --python .venv -e ".[dev]"` nachziehen.
- Das Paket macht keine Netzwerkzugriffe, keine Modellaufrufe, keine Telemetrie. Kein Import von `socket`, `urllib`, `http`, `requests`, `httpx` in `src/`.
- Bezeichner in Code und Schema Englisch. Deutsche Texte in Schweizer Rechtschreibung: nie «ß», immer «ss».
- Beispiel- und Testdaten sind synthetisch und so beschriftet. Keine realen Personen, Organisationen oder internen Abläufe.
- Gates sind Arbeitshilfen. Nirgends ein rechtliches Urteil. Jede Checkliste trägt exakt den Hinweis
  `Arbeitshilfe, keine Rechtsberatung. Offene Punkte mit der zuständigen Fachstelle klären.`
  (Konstante `DISCLAIMER` in `adoptionkit/models.py`).
- Checkfragen sind eigene Formulierungen, jede mit `source_ref`, der auf eine ID in `docs/SOURCES.md` zeigt.
- Der Begriff für die Rolle aus den Quellen (die englische Berufsbezeichnung «F… D… E…») erscheint nur in `docs/SOURCES.md` (und im vorbestehenden `docs/BAUPLAN.md`). Nicht in Code, README, CLI, Skill, Plan.
- Testgetrieben: je Lint und je Gate-Regel zuerst ein fehlschlagender Test, dann die Umsetzung.
- Commits klein und sprechend, auf Branch `stufe-0`. Jede Commit-Message endet mit
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Kein `git push`, kein `gh repo create`.
- ruff-Konfiguration wie journeykit: `line-length = 100`, `select = ["E","F","W","I","UP"]`, `ignore = ["E501"]`.
- Exit-Codes der CLI: 0 = ok, 1 = Befund/ungültig/Fehler.

## Task 2: Modelle und Schema

`src/adoptionkit/models.py` (pydantic v2, jedes Modell `model_config = ConfigDict(extra="forbid")`):

- Konstanten: `SCHEMA_VERSION = "0.1"`, `DISCLAIMER` (exakter Text oben), `PHASE_ORDER = ("discovery", "prototype", "value_proof", "hardening", "handover")`.
- Literal-Typen: `AtomType = requirement|constraint|data_source|risk|usage_signal|decision`; `SourceKind = interview|document|system|analytics|regulation|workshop`; `AtomStatus = evidenced|assumed|refuted`; `PhaseId` (fünf Werte wie `PHASE_ORDER`); `PhaseStatus = planned|running|done|aborted`; `Answer = yes|no|unclear|n/a`; `GateId = G0|G1|G2|G3|G4`; `GateResult = passed|open|stopped`; `Recommendation = guided_rollout|standard_rollout|decline`; `ChangeType = configuration|template|new_development`; `MeasureStatus = proposed|accepted|implemented|rejected`; `Fate = open|generalised|dropped`; `HostingModel = saas|private_cloud|on_premise|hybrid|unknown`.
- `Meta`: `id: str` (pattern `^[a-z0-9][a-z0-9-]*$`), `title: str`, `created: date`, `updated: date`, `schema_version: Literal["0.1"]`, `profile: str`, `synthetic: bool = False`.
- `Parties`: `client: str`, `contractor: str`, `conflict_of_interest: str | None = None`.
- `Solution`: `name: str`, `vendor: str`, `hosting_model: HostingModel = "unknown"`, `data_location: str = ""`, `config_limits: list[str] = []`.
- `Source`: `kind: SourceKind`, `ref: str | None = None`, `date: date | None = None`, `quote: str | None = None`. (`ref` ist im Schema optional, damit L001 greifen kann.)
- `Atom`: `id` (pattern `^A-\d{3}$`), `type: AtomType`, `statement: str` (min_length 1), `source: Source`, `status: AtomStatus`.
- `Phase`: `id: PhaseId`, `budget_days: int` (ge 0), `start: date | None = None`, `end: date | None = None`, `status: PhaseStatus = "planned"`, `abort_criterion: str | None = None`.
- `Check`: `id` (pattern `^G[0-4]-\d{2}$`), `question: str`, `answer: Answer = "unclear"`, `atom_refs: list[str] = []`, `source_ref: str`.
- `Gate`: `id: GateId`, `title: str`, `checks: list[Check] = []`, `result: GateResult | None = None`, `recommendation: Recommendation | None = None`, `evaluated_on: date | None = None`, `disclaimer: str = DISCLAIMER`.
- `Measure`: `id` (pattern `^M-\d{3}$`), `description: str`, `change_type: ChangeType`, `status: MeasureStatus = "proposed"`, `atom_refs: list[str] = []`, `product_decision_ref: str | None = None`.
- `EvalRun`: `id` (pattern `^R-\d{3}$`), `date: date`, `metric: str`, `value: float`.
- `Evals`: `eval_set_ref: str | None = None`, `thresholds: dict[str, float] = {}`, `runs: list[EvalRun] = []`.
- `Artefact`: `id` (pattern `^X-\d{3}$`), `description: str`, `origin_measure: str`, `fate: Fate = "open"`, `reviewed_on: date | None = None`.
- `Handover`: `operators: list[str] = []`, `training_done: bool = False`, `runbook_ref: str | None = None`.
- `Engagement`: `meta`, `parties`, `solution`, `atoms: list[Atom] = []`, `phases: list[Phase] = []`, `gates: list[Gate] = []`, `measures: list[Measure] = []`, `evals: Evals = Evals()`, `artefacts: list[Artefact] = []`, `handover: Handover = Handover()`. Hilfsmethoden: `atom(id) -> Atom | None`, `phase(id) -> Phase | None`, `gate(id) -> Gate | None`, `measure(id) -> Measure | None`.

## Task 4: Lints L001–L005

`src/adoptionkit/lints.py`:
- `@dataclass(frozen=True) class Finding: code: str; severity: Literal["error","warning"]; path: str; message: str` mit `to_dict()`.
- `RULES: dict[str, tuple[severity, beschreibung]]` für L001–L005 und L007 (Beschreibung deutsch).
- `lint(eng: Engagement, profile: Profile | None = None, today: date | None = None) -> list[Finding]`, sortiert nach `(code, path)`. L007 nur, wenn `profile` gesetzt ist (kommt in Task 5).
- Regeln (Pfadformat `<liste>/<id>`):
  - **L001 error** `atoms/<id>`: `source.ref` fehlt oder ist leer/nur Leerzeichen.
  - **L002 warning** `measures/<id>`: Measure verweist auf ein Atom vom Typ `requirement` mit Status `assumed`. Ein Befund je (Measure, Atom).
  - **L003 warning** `measures/<id>`: Measure ohne `atom_refs`.
  - **L004 error** `measures/<id>`: `change_type == "new_development"` und `product_decision_ref` fehlt, ODER der Verweis zeigt auf ein Atom, dessen Typ nicht `decision` ist.
  - **L005 error** `phases/<id>`: Phase mit Index ≥ 1 in `PHASE_ORDER` (ab `prototype`) ohne `abort_criterion` (fehlt oder leer).
- Je Regel mindestens: ein Test, der den Befund auslöst, und ein Test, der ihn nicht auslöst.

CLI: `adoptionkit lint <file> [--json]`. Datei wird zuerst validiert (ungültig → Issues, Exit 1). Text: je Befund `L002 warning measures/M-002: <message>`, dann `N Befunde (E error, W warning)`. `--json`: `{"findings": [...], "summary": {"error": E, "warning": W}}`. Exit 1, wenn mindestens ein `error`, sonst 0. In Task 4 noch ohne Profil; Task 5 ergänzt das Laden des Profils.

`src/adoptionkit/gates.py`:
- `@dataclass class GateEvaluation: gate_id; result: GateResult; recommendation: Recommendation | None; reasons: list[str]`.
- `class GateBlocked(AdoptionkitError)` mit Attribut `findings: list[Finding]`.
- `evaluate_gate(eng, profile, gate_id) -> GateEvaluation` (reine Funktion, ändert nichts). Regeln, je Regel ein Test zuerst:
  - **R1** `gate_id` nicht im Profil → `AdoptionkitError`.
  - **R2** Profil-Check fehlt im Engagement-Gate (oder Gate fehlt ganz) → wie `unclear` behandeln, Grund `"<check-id>: nicht beantwortet"`.
  - **R3** Antwort `unclear` → Ergebnis mindestens `open`, Grund `"<check-id>: unklar"`.
  - **R4** Antwort `yes`/`no` braucht mindestens einen `atom_ref` auf ein existierendes Atom mit Status `evidenced`; sonst `open`, Grund `"<check-id>: nicht belegt"`. Atome mit `assumed` oder `refuted` zählen nicht.
  - **R5** Antwort `n/a` braucht keine Atome.
  - **R6** `stopped`, wenn ein Check mit `stop_if == answer` belegt beantwortet ist (R4 erfüllt). `stopped` geht vor `open`. Grund `"<check-id>: Abbruchbedingung erfüllt"`.
  - **R7** `passed`, wenn weder `open` noch `stopped`.
  - **R8** Nur G0 bekommt eine Empfehlung: `stopped` → `decline`; `passed` und mindestens ein Check mit `guided_if == answer` → `guided_rollout`; `passed` sonst → `standard_rollout`; `open` → `None`. Andere Gates: immer `None`.
  - Checks im Engagement, die das Profil nicht kennt, werden ignoriert.
- `run_gate(eng, profile, gate_id, today) -> tuple[Engagement, GateEvaluation]`:
  - **R9** Lint zuerst (`lint(eng, profile, today)`); mindestens ein `error` → `GateBlocked`.
  - Sonst: Gate im Engagement anlegen, falls es fehlt; fehlende Checks als `unclear` ergänzen; `question` und `source_ref` aus dem Profil übernehmen; `result`, `recommendation`, `evaluated_on=today`, `disclaimer=DISCLAIMER` setzen; `meta.updated = today`. Gibt eine neue Engagement-Instanz zurück (Eingabe nicht mutieren).

L007 in `lints.py` ergänzen (Tests zuerst):
- **L007 error** `phases/<id>`: Für jedes Profil-Gate mit `required_before = P`: Phase `P` hat Status `running` oder `done`, und das Engagement-Gate fehlt oder hat `result != "passed"`. Für jedes Profil-Gate mit `required_to_complete = P`: Phase `P` hat Status `done`, und das Gate ist nicht `passed`. Message nennt Gate-ID.

CLI:
- `lint`: lädt das Profil aus `meta.profile` (Option `--profile` überschreibt) und übergibt es.
- `adoptionkit gate <file> <GATE_ID> [--profile NAME] [--today YYYY-MM-DD]`: bei `GateBlocked` die Befunde ausgeben, Exit 1, Datei unverändert. Sonst Datei zurückschreiben und ausgeben: `G0: passed`, `Empfehlung: guided_rollout` (nur wenn gesetzt), Gründe als Liste, zuletzt der Hinweis `DISCLAIMER`. Exit 0.
- `adoptionkit init <ordner> [--profile generic] [--title TEXT] [--id SLUG]`: legt `<ordner>/engagement.json` und `<ordner>/evidence/` an. Inhalt: Meta (heute, `schema_version "0.1"`, Profilname; `id` Default = Ordnername in Kleinbuchstaben, ungültige Zeichen durch `-`), `parties` und `solution` mit leeren Strings, alle fünf Phasen `planned` mit `budget_days: 0`, je Profil-Gate `gate_from_profile`.
